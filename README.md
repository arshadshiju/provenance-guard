# Provenance Guard

A backend attribution system for creative sharing platforms — classifies whether submitted content was written by a human or generated by an AI tool, scores confidence in that classification, surfaces a transparency label to users, and handles appeals from creators who believe they've been misclassified.

---

## Architecture Overview

A submitted piece of text travels through the following path:

```
POST /submit
  │
  ├─► Validation (text, creator_id, content_type)
  │
  ├─► Signal 1: LLM Classification (Groq llama-3.3-70b-versatile)
  │       → ai_probability float + reasoning string
  │
  ├─► Signal 2: Stylometric Heuristics (pure Python)
  │       → stylometric_score float + sub-metric breakdown
  │
  ├─► Signal 3: Burstiness / Perplexity Proxy (pure Python)
  │       → burstiness_score float + sub-metric breakdown
  │
  ├─► Ensemble Confidence Scorer
  │       → combined confidence float (weighted 0.50/0.30/0.20)
  │
  ├─► Transparency Label Generator
  │       → label variant + plain-language text
  │
  ├─► Audit Logger → structured JSON entry persisted to disk
  │
  └─► JSON Response to caller
```

Appeals follow a separate path:

```
POST /appeal
  │
  ├─► Validate content_id + creator_reasoning
  ├─► Lookup original entry in audit log
  ├─► Update status → "under_review"
  ├─► Append appeal_reasoning + timestamp to entry
  └─► Return confirmation JSON
```

## Detection Signals

### Signal 1: LLM Classification (Groq — weight: 0.50)

**What it measures:** Semantic and stylistic coherence evaluated holistically. The LLM assesses whether the text displays patterns characteristic of AI generation: overuse of transitional phrases ("furthermore," "it is important to note"), unnaturally balanced structure, lack of personal voice, topic coverage that feels systematically complete rather than personally selective, and hedging language that feels formulaic.

**Output format:** A float between 0.0 (clearly human) and 1.0 (clearly AI), plus a one-sentence reasoning string.

**Why this signal:** AI writing has semantic fingerprints that statistical measures miss — a human can write very formally (which confuses stylometrics) but the LLM detects that the *reasoning patterns* feel generated. This is the highest-weighted signal because it captures what structural analysis cannot.

**What it misses:** Short texts (<50 words) give insufficient context. Highly polished academic prose can fool it. Lightly edited AI output that has been personalized may score low.

---

### Signal 2: Stylometric Heuristics (weight: 0.30)

**What it measures:** Four statistical properties of writing structure that differ between human and AI text:

| Sub-metric | What it measures | Why AI differs |
|---|---|---|
| Sentence length variance | Std deviation of sentence lengths | AI generates uniform sentences; humans vary |
| Type-token ratio (TTR) | Unique words / total words | AI uses diverse vocabulary evenly; humans repeat |
| Punctuation density | Comma variance across sentences | AI punctuates formulaically; humans are stylistic |
| Formality score | Ratio of formal phrases to contractions | AI skews formal; humans use contractions |

**Output format:** Float 0.0–1.0 (higher = more AI-like) plus a breakdown of all four sub-scores.

**What it misses:** Academic and legal human writing is inherently formal and will score high. AI prompted to "be casual" will score low. Very short poems with simple vocabulary trigger false positives.

---

### Signal 3: Burstiness / Perplexity Proxy (weight: 0.20)

**What it measures:** Human writing is "bursty" — it alternates between short punchy sentences and long complex ones. AI writing maintains a narrower, more uniform rhythm. This signal also measures whether rare words are clustered (human) or evenly distributed (AI).

| Sub-metric | What it measures |
|---|---|
| Burstiness index | (std - mean) / (std + mean) of sentence lengths |
| Rare word distribution | Whether 8+ letter words cluster or spread evenly |
| Paragraph length variance | Whether paragraph lengths vary (human) or are uniform (AI) |

**Output format:** Float 0.0–1.0 plus sub-metric breakdown.

**What it misses:** Stream-of-consciousness human writing can appear uniform if very short. AI with style instructions to "vary sentence length" can bypass this signal.

## Confidence Scoring

### How signals are combined

```
confidence = (llm_score × 0.50) + (stylometric_score × 0.30) + (burstiness_score × 0.20)
```

The LLM gets the highest weight because it captures semantic patterns that structural measures cannot. Stylometrics get the second-highest weight because they are independent of the LLM's reasoning. Burstiness is the third, complementary signal.

### Threshold mapping

| Confidence | Attribution | Label Variant |
|---|---|---|
| ≥ 0.75 | likely_ai | HIGH_AI |
| 0.60 – 0.74 | likely_ai | HIGH_AI |
| 0.35 – 0.59 | uncertain | UNCERTAIN |
| 0.20 – 0.34 | likely_human | HIGH_HUMAN |
| < 0.20 | likely_human | HIGH_HUMAN |

*Note: The attribution label uses a 0.60/0.40 threshold; the transparency label uses 0.75/0.35. This means there is a "soft zone" where attribution says likely_ai but the label says uncertain — reflecting the asymmetry: false positives (mislabeling humans) are worse than false negatives.*

### Example submissions showing meaningful score variation

**High-confidence AI example:**

Input: *"Artificial intelligence represents a transformative paradigm shift in modern society. It is important to note that while the benefits of AI are numerous, it is equally essential to consider the ethical implications. Furthermore, stakeholders across various sectors must collaborate to ensure responsible deployment."*

## Transparency Label

The label shown to readers uses plain language — no technical jargon, no raw score numbers without context. All three variants are written out below.

### HIGH_CONFIDENCE_AI (confidence ≥ 0.75)

```
⚠️ Likely AI-Generated
Our analysis found strong indicators that this content may have been
generated by an AI tool. This label is shown when multiple detection
signals agree with high confidence.

Confidence: HIGH  |  Score: 87%

If you wrote this yourself, you can submit an appeal below.
Appeals are reviewed by our team within 48 hours.
```

### UNCERTAIN (confidence 0.35–0.74)

```
❓ Attribution Unclear
Our system analyzed this content but could not confidently determine
whether it was written by a person or generated by an AI tool.
This may reflect a unique writing style, mixed-origin content,
or the limits of our detection.

Confidence: UNCERTAIN  |  Score: 54%

If you are the human author, you can submit an appeal to have
this reviewed by our team.
```

### HIGH_CONFIDENCE_HUMAN (confidence < 0.35)

```
✅ Appears Human-Written
Our analysis found strong indicators that this content was written
by a person. Multiple signals consistent with human authorship
were detected.

Confidence: HIGH  |  Score: 18%
```

### VERIFIED_HUMAN (Provenance Certificate — stretch feature)

```
🏅 Verified Human-Written
This creator has completed an additional verification step confirming
this work is their own original writing.
Verified via: Process Description.

Status: VERIFIED
```

The label variants are meaningfully different: the HIGH_AI label includes a warning emoji and explicitly prompts appeal; the UNCERTAIN label acknowledges system limitations; the HIGH_HUMAN label is affirming and requires no action. A non-technical reader can immediately understand what each label means without knowing what a "classifier" or "confidence score" is.

## Rate Limiting

Rate limits applied to `/submit`: **10 requests per minute; 100 requests per day** (per IP address).

**Reasoning:**

- A real writer submitting their own creative work might post 1–5 pieces in a session, with a realistic burst of 10 in one minute only in edge cases (bulk-uploading a backlog). The per-minute limit accommodates this while blocking rapid scripted submission.
- 100 per day is generous for a legitimate user but makes large-scale automated flooding expensive.
- The per-minute limit specifically targets the adversarial pattern: a script sending hundreds of texts to probe the classifier's decision boundaries.
- The `/appeal` endpoint is limited to 30 per hour — appeals are human actions and don't need high throughput.

## Provenance Certificate (Stretch Feature)

A creator who wants to officially attest to human authorship can earn a **Provenance Certificate** via `POST /certify`. They provide:

- `content_id` — the ID from their submission
- `verification_method` — one of: `declaration` (sworn statement), `process_description` (description of their writing process), or `metadata_proof` (file metadata showing human creation)
- `verification_detail` — the actual attestation (min 20 characters)

The system issues a certificate ID (e.g., `PG-CERT-3F7A2B1E`) and updates the content's status to `verified_human`. The label displayed on the content changes to the distinct "🏅 Verified Human-Written" badge, which is visually different from all three standard labels.

**Restriction:** Content classified as `likely_ai` must go through the appeal process first before a certificate can be issued.

## Multi-Modal Support (Stretch Feature)

The system handles a second content type: **structured metadata** (e.g., image EXIF data or file metadata).

Submit with `content_type: "metadata"` and a `metadata` dict:

```bash
curl -X POST http://localhost:5000/submit \
  -H "Content-Type: application/json" \
  -d '{
    "text": "metadata submission",
    "creator_id": "photographer-1",
    "content_type": "metadata",
    "metadata": {
      "software": "Stable Diffusion v2.1",
      "Model": null,
      "DateTime": "2025-06-01T10:00:00"
    }
  }'
```

The metadata pipeline checks for: AI software tags in the `software` field (Stable Diffusion, Midjourney, DALL-E, etc.), missing camera model, identical creation/modification timestamps, and explicit AI prompt fields. It returns `metadata_flags` listing every indicator found.

This pipeline is intentionally separate from the text pipeline — stylometrics do not apply to EXIF data. The result includes the same structured response format (`content_id`, `attribution`, `confidence`, `label`) so downstream consumers can treat it uniformly.

## Known Limitations

**Formal academic or professional writing:** The single most likely false-positive scenario. A scholar, lawyer, or journalist writing in dense, passive-voice prose will trigger high stylometric AI scores (high formality, low TTR, uniform sentence length). The LLM may also be misled by the structural regularity. The UNCERTAIN zone (0.35–0.75) is intentionally wide to absorb this case, and the label text explicitly names "unique writing style" as a possible cause. But a confidence score of 0.70 on a genuine academic paper is a real failure mode.

**Non-native English speakers writing formally:** A non-native speaker following grammar rules strictly (avoiding contractions, using complete sentences) will produce text that triggers multiple AI signals simultaneously. This is arguably the most ethically serious limitation — the system could disproportionately flag writers whose English is rule-following rather than idiomatic. The appeal flow is the mitigation; the label text acknowledges this explicitly.

## Spec Reflection

**One way the spec helped:** Writing out the three label variants before building the label generator function was genuinely useful. When I got to implementation, I had exact strings to match against — there was no ambiguity about what "uncertain" should say. The spec also forced me to think through the false-positive asymmetry (a false positive is worse than a false negative) before writing the confidence thresholds, which is why the UNCERTAIN zone is wider than a simple 0.5 split.

**One way implementation diverged:** The planning doc defined five threshold levels (HIGH_AI, LEAN_AI, UNCERTAIN, LEAN_HUMAN, HIGH_HUMAN). In implementation, LEAN_AI and LEAN_HUMAN were collapsed into UNCERTAIN for the transparency label. This happened because showing a "Lean AI" label to a user sounded more alarming than "Uncertain" without being more informative — and the hint about false positives being worse than false negatives made me more conservative about displaying any AI label below 0.75 confidence. The five levels are still in the confidence scoring logic; they just don't all map to distinct displayed labels.

## AI Usage

### Instance 1: Generating the stylometric signal function

**Directed:** Provided Signal 2 spec section and architecture diagram. Asked Claude to generate a `stylometric_signal()` function in Python that computes sentence length variance, type-token ratio, punctuation density, and formality score, combining them into a weighted 0–1 float.

**Output:** Claude generated a function with the four sub-metrics. The formality score initially used a simple keyword count without normalizing by word count, which meant longer texts always scored higher. I overrode this by dividing all raw counts by `word_count` before computing the ratio.

**Revised:** Also removed a fifth metric Claude added ("passive voice detection via regex") because the regex was unreliable — it matched "was" in any context including past tense, not just true passive constructions. Dropped it rather than ship a broken metric.

### Instance 2: Generating the confidence scoring and label generator

**Directed:** Provided the uncertainty representation section (thresholds table) and the three label variant text blocks. Asked Claude to generate `combine_scores()` and `generate_label()` that matched those exact thresholds and returned the exact strings.

**Output:** Claude implemented the weighting correctly but used a single 0.5 threshold — above 0.5 → AI, below 0.5 → human. This was simpler than my spec's asymmetric thresholds.

**Revised:** I replaced the threshold logic with the three-zone approach from planning.md (≥0.75, 0.35–0.74, <0.35) and verified that all four test inputs produced the expected label variant. The asymmetric zones are a deliberate design choice, not a default, and the generated code would have silently ignored it.
